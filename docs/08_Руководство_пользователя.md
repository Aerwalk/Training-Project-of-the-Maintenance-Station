# Руководство пользователя

**Приложение Б к отчёту по практике**  
**Наименование:** модуль доступа к базе данных станции технического обслуживания автомобилей «СТО»  
**Шифр:** УП.01.02-ПМ.01-СТО  
**Версия:** 1.0  
**Дата:** 10.11.2026

## 1. Назначение документа

Руководство описывает установку, настройку и порядок работы с учебным приложением `sto-db-module`. Документ предназначен для студента-разработчика, преподавателя, администратора учебного стенда и сотрудника СТО, использующего демонстрационную версию.

Приложение работает в двух режимах:

* **веб-режим** `--web` — REST API и одностраничный интерфейс в браузере (основной способ работы, раздел 9);
* **консольный режим** — интерактивное меню и demo-сценарий для демонстрации модуля доступа к данным (раздел 8).

Оба режима используют одну и ту же базу PostgreSQL и одинаковые бизнес-правила: хранимые функции, триггеры и ограничения целостности.

## 2. Требования к окружению

| Компонент | Минимальные требования |
|---|---|
| Операционная система | Windows 10/11, Linux или macOS |
| Java | JDK 23 |
| Node.js | 20+ и npm 10+ (сборка фронтенда) |
| Docker | Docker Desktop 4.x или Docker Engine 24+ с плагином Compose |
| Свободные порты | `5434` (PostgreSQL), `8080` (REST API и веб-интерфейс), `4200` (dev-сервер Angular) |
| Свободное место | около 500 МБ для образа PostgreSQL и тома, 300 МБ для `node_modules` |
| Браузер | Chrome, Edge, Firefox или Safari актуальной версии |
| Терминал | PowerShell, Windows Terminal, Bash или IDE-консоль |

Проверить версии:

```powershell
java -version
node --version
npm --version
docker --version
docker compose version
```

Ожидаемый результат: Java 23, Node.js 20+, Docker 24+ и Docker Compose v2. Если команда `docker compose` недоступна, используйте `docker-compose`.

## 4. Установка и первый запуск

### 4.1. Запуск базы данных

Из корневого каталога проекта выполните:

```powershell
docker compose up -d
docker compose ps
```

Контейнер `sto-postgres` должен находиться в состоянии `healthy`. При первом запуске автоматически создаются:

* схема, роли, функции и триггеры из `sto.sql`;
* демонстрационные пользователи, клиенты, автомобили, услуги и заявки из `docker/init/02_seed.sql`.

Проверка готовности БД:

```powershell
docker exec sto-postgres pg_isready -U postgres -d sto
```

Ожидаемый ответ: `/var/run/postgresql:5432 - accepting connections` (внутри контейнера используется порт 5432, снаружи — 5434).

### 4.2. Сборка приложения

Windows:

```powershell
.\mvnw.cmd clean package
```

Linux/macOS:

```bash
./mvnw clean package
```

При первой сборке Maven скачает зависимости. Успешная сборка заканчивается сообщением `BUILD SUCCESS` и создаёт `target/sto-db-module.jar`.

### 4.3. Сборка веб-интерфейса

```powershell
cd frontend
npm ci
npm run build
cd ..
```

Результат сборки — каталог `frontend/dist/sto-frontend/browser`, который режим `--web` раздаёт по адресу `http://localhost:8080/`. Для разработки вместо `npm run build` можно запустить `npm start` (порт `4200`, горячая перезагрузка), но Java-сервер `--web` при этом должен работать отдельно.

### 4.4. Проверка подключения

```powershell
java -jar target\sto-db-module.jar --check
```

Ожидаемый вывод:

```
Подключение успешно. url=jdbc:postgresql://localhost:5434/sto, username=sto_admin, poolSize=5, connectionTimeoutMs=3000, retryMaxAttempts=4
PostgreSQL: PostgreSQL 16.x ...
```

Если команда завершилась ошибкой, см. раздел 10 «Типичные ошибки».

## 5. Режимы запуска

| Команда | Назначение |
|---|---|
| `java -jar target\sto-db-module.jar` | интерактивное меню с входом по логину и паролю |
| `java -jar target\sto-db-module.jar --check` | проверка соединения и версия PostgreSQL |
| `java -jar target\sto-db-module.jar --demo` | автоматический сквозной сценарий (создаёт реальную заявку) |
| `java -jar target\sto-db-module.jar --list-orders` | вывод списка заявок без входа в систему |
| `java -jar target\sto-db-module.jar --web` | REST API и веб-интерфейс на `http://localhost:8080` |
| `java -jar target\sto-db-module.jar --help` | краткая справка по режимам |

> **Важно:** режим `--demo` не является «сухим» прогоном. Он создаёт новую заявку, добавляет в неё услуги и закрывает её. Для повторной демонстрации на чистых данных выполните `docker compose down -v` и `docker compose up -d`.

## 6. Настройка подключения

Параметры по умолчанию находятся в файле `src/main/resources/application.properties`:

```properties
db.url=jdbc:postgresql://localhost:5434/sto
db.username=sto_admin
db.password=admin_pass
db.pool.maximumPoolSize=5
db.retry.maxAttempts=4
```

Приоритет источников (от высшего к низшему):

1. переменные окружения `STO_DB_URL`, `STO_DB_USERNAME`, `STO_DB_PASSWORD`, `STO_DB_MAX_POOL_SIZE`, `STO_DB_RETRY_MAX_ATTEMPTS`;
2. внешний файл, указанный параметром JVM `-Dconfig.file=<путь>`;
3. `application.properties` в classpath.

Пример запуска с другим паролем (PowerShell):

```powershell
$env:STO_DB_PASSWORD = "другой_пароль"
java -jar target\sto-db-module.jar --check
```

Пример с внешним файлом:

```powershell
java "-Dconfig.file=D:\sto\application.properties" -jar target\sto-db-module.jar
```

Обратите внимание: в PowerShell аргумент `-D...` нужно заключать в кавычки, иначе оболочка интерпретирует его по-своему.

## 7. Роли и учётные записи

Демонстрационные пользователи создаются скриптом `docker/init/02_seed.sql`:

| Логин | Пароль | Роль | Доступные возможности |
|---|---|---|---|
| `admin` | `admin123` | администратор | полный доступ к меню |
| `manager` | `manager123` | мастер-приёмщик | заявки, клиенты, услуги, создание и закрытие заявок, журнал |
| `master` | `master123` | автомобильный мастер | те же операции персонала |
| `client` | `client123` | клиент СТО | просмотр заявок, услуг, стоимости и своих заявок |

Пароли хранятся в БД в виде bcrypt-хешей и проверяются функцией PostgreSQL `crypt()`. В приложении и логах пароли не сохраняются.

Разграничение доступа является **учебным**: в консольном меню скрываются пункты для роли `client`, а в веб-интерфейсе часть действий ограничена навигацией, но API не проверяет токены и права. Ограничения прав подробно описаны в [05_Безопасность.md](05_Безопасность.md).

## 8. Работа с интерактивным меню

### 8.1. Вход в систему

Запустите приложение без параметров:

```powershell
java -jar target\sto-db-module.jar
```

Введите логин и пароль. При неверных данных выдаётся сообщение «Неверный логин или пароль» и предоставляется ещё одна попытка — всего их три. После третьей неудачной попытки приложение завершает работу.

Пароль не отображается при вводе, если запуск выполнен в терминале с поддержкой `System.console()`. В IDE и некоторых перенаправленных потоках пароль вводится обычной строкой.

### 8.2. Пункты меню

Состав меню зависит от роли. Для персонала (`admin`, `manager`, `master`):

| Пункт | Действие | Что происходит в БД |
|---|---|---|
| 1 | Список заявок | чтение представления `v_order_total` |
| 2 | Список клиентов | чтение таблицы `clients` |
| 3 | Автомобили клиента | чтение `cars` по `client_id` |
| 4 | Список услуг | чтение справочника `services` |
| 5 | Создать заявку | вызов функции `create_order` |
| 6 | Добавить услугу | вызов функции `add_service_to_order` |
| 7 | Закрыть заявку | вызов функции `close_order` |
| 8 | Рассчитать стоимость | вызов функции `calculate_order_total` |
| 9 | Заявки клиента | вызов функции `get_client_orders` |
| 10 | Журнал статусов | чтение `order_status_log` |
| 11 | Проверить соединение | `SELECT version()` через пул |
| 0 | Выход | закрытие пула и завершение приложения |

Для роли `client` доступны пункты 1, 4, 8, 9, 11 и 0. При выборе скрытого пункта выводится сообщение «Недостаточно прав для этой операции».

### 8.3. Просмотр заявок

Выберите пункт `1`. Приложение выведет таблицу:

```
ID   Клиент                           Авто          Статус          Стоимость
--------------------------------------------------------------------------------
1    Иванов Иван Иванович             А123ВС64      новая              0.00
3    Сидоров Алексей Петрович         С789МН64      завершена       5500.00
```

Стоимость рассчитывается представлением `v_order_total` на основании услуг, добавленных в заявку, с учётом зафиксированной цены `price_at`.

### 8.4. Создание заявки

1. Выберите пункт `5`.
2. Приложение покажет список клиентов. Введите `ID клиента`.
3. Выберите автомобиль из списка автомобилей этого клиента.
4. Выберите мастера или введите `0`, чтобы создать заявку без мастера.
5. Введите описание неисправности (обязательное поле, до 2000 символов).

После успешного создания выводится номер заявки, например «Создана заявка №14».

Проверки, которые выполняет приложение:

* клиент и автомобиль должны существовать;
* автомобиль должен принадлежать выбранному клиенту;
* описание не должно быть пустым или длиннее 2000 символов;
* выбранный мастер должен существовать и быть активным.

### 8.5. Добавление услуги в заявку

1. Выберите пункт `6`.
2. Приложение покажет справочник услуг с ценами.
3. Введите `ID заявки`, `ID услуги` и количество от 1 до 100.

Цена услуги фиксируется в момент добавления (`order_services.price_at`), поэтому последующее изменение прайса не меняет стоимость уже оказанной услуги.

Запрещено добавлять услуги в заявку со статусом «завершена» или «отменена». Ограничение действует и в приложении, и в триггере БД.

### 8.6. Закрытие заявки

1. Выберите пункт `7`.
2. Введите `ID заявки`.

После закрытия:

* статус заявки становится «завершена»;
* триггер заполняет `closed_at`;
* в журнал `order_status_log` автоматически добавляется запись;
* приложение выводит итоговую стоимость.

Повторное закрытие завершённой заявки отклоняется сообщением «Заявка уже завершена». Отменённую заявку завершить нельзя.

### 8.7. Расчёт стоимости и заявки клиента

* Пункт `8` запрашивает `ID заявки` и выводит сумму через `calculate_order_total`.
* Пункт `9` запрашивает `ID клиента` и выводит его заявки: номер, автомобиль, статус, стоимость и дату создания.

Сумма из пункта `8` должна совпадать со стоимостью в пункте `1` для той же заявки — это проверяется автоматическим тестом `viewTotalEqualsStoredFunctionResult`.

### 8.8. Журнал статусов

Пункт `10` доступен персоналу. Можно ввести `ID заявки`, чтобы увидеть историю только по ней, или нажать `Enter`, чтобы вывести весь журнал.

```
ID   Заявка Было     Стало    Когда                Кто
--------------------------------------------------------------------------------
1    3      1        4        2026-11-10 12:34:56  sto_admin
```

Журнал ведётся триггером `trigger_log_order_status` и не редактируется из приложения.

## 9. Работа с веб-интерфейсом

### 9.1. Запуск и вход

1. Убедитесь, что контейнер `sto-postgres` запущен и БД инициализирована.
2. Соберите приложение и фронтенд (разделы 4.2–4.3).
3. Запустите сервер:

   ```powershell
   java -jar target\sto-db-module.jar --web
   ```

4. Откройте в браузере `http://localhost:8080/`.
5. Введите логин и пароль из раздела 7. Логин не чувствителен к регистру: `admin` и `Admin` равнозначны.

На странице входа есть чипы демонстрационных учётных записей — нажатие подставляет логин и пароль. После успешного входа открывается дашборд. Сведения о пользователе сохраняются в `localStorage` браузера, поэтому перезагрузка страницы не требует повторного входа; кнопка «Выйти» в нижней части sidebar очищает эти данные.

### 9.2. Дашборд «Обзор»

Раздел показывает сводку по сервису:

* карточки «Заявки», «В работе», «Завершено», «Стоимость работ»;
* диаграмму распределения заявок по статусам;
* таблицу активных заявок (новые и в работе) со ссылками на карточку;
* количество записей в справочниках;
* последние события журнала статусов;
* процент завершённых заявок и средний чек.

Кнопка «Обновить» повторно читает данные из БД, «Новая заявка» открывает форму создания.

### 9.3. Заявки

Экран «Заявки» — основной рабочий инструмент:

* вкладки-фильтры «Все», «Новые», «В работе», «Завершённые», «Отменённые»;
* поиск по номеру, клиенту и автомобилю;
* кнопка «Новая заявка»: выбор клиента, затем его автомобиля, мастера (необязательно) и описание неисправности;
* нажатие на строку открывает карточку заявки: клиент, автомобиль, мастер, суммы, услуги и история статусов;
* в карточке можно добавить услугу с количеством от 1 до 100; цена фиксируется на момент добавления;
* кнопка «Завершить заявку» показывает подтверждение, меняет статус, заполняет `closed_at` и добавляет запись в журнал через триггер БД.

После каждой операции показывается toast-уведомление, а таблица и карточка обновляются данными из API. Добавлять услуги и закрывать можно только заявки в статусах «новая» и «в работе».

### 9.4. Клиенты

Экран показывает карточки клиентов с телефоном, e-mail и количеством автомобилей.

* «Добавить клиента» — форма с ФИО, телефоном и необязательным e-mail;
* нажатие на карточку открывает окно с контактами, автомобилями и историей заявок;
* из окна можно создать заявку или добавить автомобиль — клиент подставится автоматически.

### 9.5. Автомобили

Карточки автомобилей содержат марку, модель, год, госномер, VIN и владельца.

* «Добавить автомобиль» — выбор клиента, марка, модель, год, номер и VIN;
* переход по владельцу открывает карточку клиента;
* поиск работает по марке, модели, номеру, VIN и имени владельца.

### 9.6. Услуги

Прайс-лист с ценой и нормативной длительностью. Доступны поиск по названию и сортировка «По названию», «Сначала дешевле», «Сначала дороже». Кнопка «Добавить услугу» создаёт новую позицию прайса; цена должна быть больше нуля, длительность — необязательное положительное число.

### 9.7. Мастера

Карточки мастеров показывают специализацию, признак активности и текущую загрузку — количество активных заявок («новая» и «в работе»). Загрузка рассчитывается API `GET /api/masters/workload`. Новый мастер создаётся вместе с пользователем в БД, поэтому через интерфейс доступен только просмотр.

### 9.8. Журнал статусов

Журнал формируется триггером `trigger_log_status_change` при каждом изменении статуса заявки. Доступны:

* фильтр по конкретной заявке;
* поиск по клиенту, автомобилю и автору изменения;
* группировка записей по дням.

Журнал доступен только для чтения и не редактируется из интерфейса.

### 9.9. Типичные проблемы веб-режима

| Симптом | Причина | Решение |
|---|---|---|
| На `/` ответ 404 с подсказкой | фронтенд не собран | выполнить `npm ci` и `npm run build` в каталоге `frontend` |
| Страница открылась, но данные не загружаются | не запущен `--web` или занят порт `8080` | проверить консоль сервера, освободить порт или задать `STO_WEB_PORT` |
| «Неверный логин или пароль» | неверные данные или БД не инициализирована | проверить учётную запись из раздела 7 и `docker compose ps` |
| После перезапуска API интерфейс показывает старую версию | браузер кэшировал файлы | обновить страницу с `Ctrl+F5` |
| Вход выполнен, но список пуст | в БД нет данных после `down -v` | пересоздать стенд и дождаться выполнения init-скриптов |

## 10. Типичные ошибки и способы устранения

| Сообщение | Причина | Что делать |
|---|---|---|
| `Не удалось подключиться к БД за 4 попыт(ки)...` | контейнер не запущен, неверный порт или пароль | выполнить `docker compose ps`, проверить `db.url`, `db.username`, `db.password` |
| `Connection refused` / `08001` | PostgreSQL недоступен | запустить `docker compose up -d`, проверить порт `5434` |
| `28P01` / таймаут при неверном пароле | неверные учётные данные роли БД | исправить `db.password` или `STO_DB_PASSWORD` |
| `Неверный логин или пароль` | неверные данные пользователя приложения | использовать учётную запись из раздела 7 |
| `Превышено количество попыток входа` | три неудачных входа подряд | перезапустить приложение и проверить раскладку клавиатуры |
| `Ошибка: Клиент с id=... не найден` | введён несуществующий ID | посмотреть список клиентов в пункте `2` |
| `Ошибка: Автомобиль ... принадлежит другому клиенту` | несоответствие пары клиент—автомобиль | выбрать автомобиль из списка, предложенного приложением |
| `Ошибка: Количество должно быть от 1 до 100` | введено 0, отрицательное число или больше 100 | ввести корректное количество |
| `Ошибка: Нельзя добавить услугу в заявку со статусом «завершена»` | заявка уже закрыта | создать новую заявку |
| `Ошибка: Заявка уже завершена` | повторное закрытие | выбрать другую заявку |
| `Ошибка: Описание неисправности обязательно` | пустое описание | ввести текст неисправности |
| `Ошибка БД: ... SQLState: 23505` | дубликат уникального значения | изменить телефон, номер или VIN |
| `Ошибка БД: ... SQLState: 23503` | нарушена ссылочная целостность | проверить, что клиент, автомобиль и услуга существуют |
| `Ошибка БД: ... SQLState: 57014` | превышено время выполнения запроса | повторить операцию или обратиться к администратору |
| Кириллица отображается некорректно | кодировка терминала | использовать Windows Terminal или выполнить `chcp 65001` |

Полный перечень ожидаемых ошибок приведён в [expected-errors.md](expected-errors.md).

## 11. Остановка и повторный запуск

Остановить приложение можно пунктом `0` (в консольном режиме) или сочетанием `Ctrl+C` в терминале, где запущен сервер. Для веб-режима достаточно остановить процесс `--web`.

Остановить БД без потери данных:

```powershell
docker compose stop
```

Запустить снова:

```powershell
docker compose start
```

Полностью удалить данные и пересоздать стенд:

```powershell
docker compose down -v
docker compose up -d
```

> Команда `down -v` **удаляет все данные**: заявки, клиентов, автомобили и журнал. Используйте её только для возврата к исходному демонстрационному состоянию.

## 12. Резервное копирование и восстановление

Создать дамп базы:

```powershell
docker exec sto-postgres pg_dump -U postgres -d sto -F c -f /tmp/sto.dump
docker cp sto-postgres:/tmp/sto.dump .\sto.dump
```

Восстановить из дампа:

```powershell
docker cp .\sto.dump sto-postgres:/tmp/sto.dump
docker exec sto-postgres pg_restore -U postgres -d sto --clean --if-exists /tmp/sto.dump
```

Для учебного стенда резервное копирование не является обязательным, но позволяет сохранить результаты демонстрации.

## 13. Ограничения учебной версии

* веб-интерфейс не выдаёт токенов и не проверяет права на уровне API: сведения о пользователе хранятся в `localStorage`, ограничения ролей действуют в основном в навигации;
* роль `client` не изолирует данные на уровне SQL: клиент видит список всех заявок (риск SEC-01);
* приложение подключается к БД под ролью `sto_admin` с широкими правами (риск SEC-02);
* роль `master` имеет право напрямую изменять `closed_at` (риск SEC-03);
* пароли демонстрационных пользователей и роли БД находятся в репозитории (риск SEC-04);
* соединение с PostgreSQL не защищено TLS (риск SEC-05);
* порт `5434` опубликован на все интерфейсы хоста (риск SEC-08);
* отсутствует журналирование действий пользователя на уровне приложения.

Меры по устранению рисков и приоритеты приведены в [05_Безопасность.md](05_Безопасность.md).

## 14. Часто задаваемые вопросы

**Нужно ли устанавливать PostgreSQL отдельно?**  
Нет. PostgreSQL поставляется в Docker-образе и запускается через `docker compose`.

**Можно ли использовать другой порт?**  
Да. Измените проброс порта в `docker-compose.yml` и значение `db.url` в `application.properties` или переменной `STO_DB_URL`.

**Почему `--demo` каждый раз создаёт новую заявку?**  
Сценарий специально выполняет полный цикл записи, чтобы продемонстрировать работу функций и триггеров. Для сброса данных используйте `docker compose down -v`.

**Нужно ли собирать фронтенд перед каждым запуском `--web`?**  
Только после изменений в `frontend/`. Если каталог `frontend/dist/sto-frontend/browser` уже существует, сервер раздаёт готовые файлы. При первом запуске выполните `npm ci` и `npm run build`.

**Почему при `npm start` данные не загружаются?**  
Dev-сервер Angular работает на порту `4200`, а API — на `8080`. Запустите `java -jar target\sto-db-module.jar --web` параллельно: фронтенд обращается к абсолютному адресу `http://localhost:8080/api`.

**Можно ли изменить порт веб-сервера?**  
Да. Задайте переменную окружения `STO_WEB_PORT` перед запуском, например `$env:STO_WEB_PORT = "9090"`. Адрес API в `frontend/src/app/core/api.service.ts` при этом нужно изменить и пересобрать фронтенд.

**Почему интеграционные тесты пропускаются?**  
Если контейнер PostgreSQL не запущен, интеграционные тесты помечаются как skipped. Запустите `docker compose up -d` и повторите `.\mvnw.cmd test`.

**Где посмотреть результаты тестирования?**  
В [04_Результаты_тестирования.md](04_Результаты_тестирования.md) и каталоге `docs/evidence/`.

**Что делать при ошибке `function create_order(...) does not exist` при старте контейнера?**  
Убедиться, что используется исправленная версия `sto.sql`, в которой блок `GRANT EXECUTE` расположен после создания функций. Затем пересоздать том: `docker compose down -v` и `docker compose up -d`.
