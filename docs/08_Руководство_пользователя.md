# Руководство пользователя

**Приложение Б к отчёту по практике**  
**Наименование:** модуль доступа к базе данных станции технического обслуживания автомобилей «СТО»  
**Шифр:** УП.01.02-ПМ.01-СТО  
**Версия:** 1.1  
**Дата:** 12.11.2026

## 1. Назначение документа

Руководство описывает установку, настройку и порядок работы с учебным приложением `sto-db-module`. Документ предназначен для студента-разработчика, преподавателя, администратора учебного стенда и сотрудника СТО, использующего демонстрационную версию.

Приложение работает в двух режимах:

* **графический интерфейс JavaFX** — основной способ работы: окно с боковым меню, карточками, таблицами и модальными окнами (раздел 8);
* **консольный режим** `--console` — интерактивное меню и demo-сценарий для демонстрации модуля доступа к данным (раздел 9).

Оба режима используют одну и ту же базу PostgreSQL и одинаковые бизнес-правила: хранимые функции, триггеры и ограничения целостности. JavaFX-клиент обращается к сервисам `AuthService`, `CatalogService` и `OrderService` напрямую, без HTTP и JSON.

## 2. Требования к окружению

| Компонент | Минимальные требования |
|---|---|
| Операционная система | Windows 10/11, Linux или macOS с графической средой |
| Java | JDK 23 |
| Docker | Docker Desktop 4.x или Docker Engine 24+ с плагином Compose |
| Свободный порт | `5434` для PostgreSQL |
| Свободное место | около 500 МБ для образа PostgreSQL и тома |
| Терминал | PowerShell, Windows Terminal, Bash или IDE-консоль |

Отдельная установка JavaFX SDK не требуется: JavaFX 23.0.1 подключается как Maven-зависимость и входит в исполняемый jar.

Проверить версии:

```powershell
java -version
docker --version
docker compose version
```

Ожидаемый результат: Java 23 и Docker 24+. Если команда `docker compose` недоступна, используйте `docker-compose`.

## 4. Установка и первый запуск

### 4.1. Запуск базы данных

Из корневого каталога проекта выполните:

```powershell
docker compose up -d
docker compose ps
```

Контейнер `sto-postgres` должен находиться в состоянии `healthy`. При первом запуске автоматически создаются:

* схема, роли, функции и триггеры из `sto.sql`;
* демонстрационные пользователи, клиенты, автомобили, услуги и заявки из `docker/init/02_seed.sql`.

Проверка готовности БД:

```powershell
docker exec sto-postgres pg_isready -U postgres -d sto
```

Ожидаемый ответ: `/var/run/postgresql:5432 - accepting connections` (внутри контейнера используется порт 5432, снаружи — 5434).

### 4.2. Сборка приложения

Windows:

```powershell
.\mvnw.cmd clean package
```

Linux/macOS:

```bash
./mvnw clean package
```

При первой сборке Maven скачает зависимости, включая JavaFX и платформенные библиотеки. Успешная сборка заканчивается сообщением `BUILD SUCCESS` и создаёт `target/sto-db-module.jar`.

### 4.3. Запуск графического интерфейса

```powershell
java -jar target\sto-db-module.jar
```

Откроется окно «СТО · управление автосервисом». Приложение проверит соединение с PostgreSQL, покажет экран входа, а после успешной аутентификации — основную оболочку с разделами.

Для запуска из исходников без сборки jar:

```powershell
.\mvnw.cmd javafx:run
```

При первом запуске этой команды Maven также скачает JavaFX.

### 4.4. Проверка подключения

```powershell
java -jar target\sto-db-module.jar --check
```

Ожидаемый вывод:

```
Подключение успешно. url=jdbc:postgresql://localhost:5434/sto, username=sto_admin, poolSize=5, connectionTimeoutMs=3000, retryMaxAttempts=4
PostgreSQL: PostgreSQL 16.x ...
```

Если команда завершилась ошибкой, см. раздел 10 «Типичные ошибки».

## 5. Режимы запуска

| Команда | Назначение |
|---|---|
| `java -jar target\sto-db-module.jar` | графический интерфейс JavaFX (основной режим) |
| `java -jar target\sto-db-module.jar --console` | интерактивное меню в терминале |
| `java -jar target\sto-db-module.jar --demo` | автоматический сквозной сценарий (создаёт реальную заявку) |
| `java -jar target\sto-db-module.jar --check` | проверка соединения и версии PostgreSQL |
| `java -jar target\sto-db-module.jar --list-orders` | вывод списка заявок без входа в систему |
| `java -jar target\sto-db-module.jar --help` | краткая справка по режимам |

> **Важно:** режим `--demo` не является «сухим» прогоном. Он создаёт новую заявку, добавляет в неё услуги и закрывает её. Для повторной демонстрации на чистых данных выполните `docker compose down -v` и `docker compose up -d`.

## 6. Настройка подключения

Параметры по умолчанию находятся в файле `src/main/resources/application.properties`:

```properties
db.url=jdbc:postgresql://localhost:5434/sto
db.username=sto_admin
db.password=admin_pass
db.pool.maximumPoolSize=5
db.retry.maxAttempts=4
```

Приоритет источников (от высшего к низшему):

1. переменные окружения `STO_DB_URL`, `STO_DB_USERNAME`, `STO_DB_PASSWORD`, `STO_DB_MAX_POOL_SIZE`, `STO_DB_RETRY_MAX_ATTEMPTS`;
2. внешний файл, указанный параметром JVM `-Dconfig.file=<путь>`;
3. `application.properties` в classpath.

Пример запуска с другим паролем (PowerShell):

```powershell
$env:STO_DB_PASSWORD = "другой_пароль"
java -jar target\sto-db-module.jar
```

Пример с внешним файлом:

```powershell
java "-Dconfig.file=D:\sto\application.properties" -jar target\sto-db-module.jar
```

Обратите внимание: в PowerShell аргумент `-D...` нужно заключать в кавычки, иначе оболочка интерпретирует его по-своему.

Если база недоступна, вместо экрана входа откроется страница ошибки с кнопками «Повторить подключение» и «Закрыть приложение». После запуска контейнера нажмите «Повторить подключение» — перезапускать приложение не нужно.

## 7. Роли и учётные записи

Демонстрационные пользователи создаются скриптом `docker/init/02_seed.sql`:

| Логин | Пароль | Роль | Назначение |
|---|---|---|---|
| `admin` | `admin123` | администратор | полный доступ ко всем разделам и операциям |
| `manager` | `manager123` | мастер-приёмщик | заявки, клиенты и автомобили, просмотр прайса и журнала |
| `master` | `master123` | автомобильный мастер | заявки, добавление услуг и закрытие, просмотр справочников |
| `client` | `client123` | клиент СТО | только собственные заявки и прайс-лист |

Логин вводится без учёта регистра: `admin` и `Admin` равнозначны. Пароли хранятся в БД в виде bcrypt-хешей и проверяются функцией PostgreSQL `crypt()`. В приложении и логах пароли не сохраняются.

Разграничение доступа действует и в JavaFX-интерфейсе, и в консольном меню:

| Возможность | admin | manager | master | client |
|---|:---:|:---:|:---:|:---:|
| Обзор, клиенты, автомобили, мастера | да | да | да | — |
| Заявки | все | все | все | только свои |
| Создание заявки | да | да | — | — |
| Добавление услуг и закрытие заявки | да | да | да | — |
| Создание клиентов и автомобилей | да | да | — | — |
| Просмотр услуг | да | да | да | да |
| Создание услуг | да | — | — | — |
| Журнал статусов | да | да | — | — |

Меню строится по правам роли: недоступные разделы и кнопки не отображаются, а сервисы повторно проверяют право перед выполнением операции. Учётная запись `client` привязана к карточке клиента Иванова через `users.client_id`, поэтому в разделе «Заявки» он видит только заявки №1 и №4. Приложение подключается к БД под ролью `sto_admin`; ограничения ролей PostgreSQL описаны в [05_Безопасность.md](05_Безопасность.md).

### 7.1. Создание учётной записи через SQL

Нового пользователя можно добавить без JavaFX-интерфейса — функцией `create_account()`. Она создаётся вместе со схемой при первом запуске контейнера (`sto.sql`), поэтому доступна сразу после `docker compose up -d`. Пароль указывается в вызове в открытом виде, но в БД попадает только bcrypt-хеш: функция `app_hash_password()` хеширует его внутри PostgreSQL.

Подключение к БД:

```powershell
docker exec -it sto-postgres psql -U postgres -d sto
```

Новый клиент (создаётся и карточка в `clients`, и учётная запись):

```sql
SELECT create_account(
    'ivanov',                 -- логин, регистр не важен
    'ClientPass123',          -- пароль, не короче 8 символов
    'Иванов Иван Иванович',
    'client',
    '+7 900 111-22-33',       -- телефон
    'ivanov@example.com'      -- e-mail (необязателен)
);
```

Новый сотрудник (карточка клиента не создаётся):

```sql
SELECT create_account('petrov', 'MasterPass123', 'Петров Пётр', 'master');
```

Привязка к уже существующей карточке клиента (у Петровой из демонстрационных данных id = 2):

```sql
SELECT create_account(
    'petrova', 'ClientPass456', 'Петрова Мария Сергеевна', 'client',
    p_client_id => 2
);
```

Порядок аргументов: логин, пароль, ФИО, роль (`admin`, `manager`, `master`, `client`), телефон, e-mail, id существующей карточки клиента. Обязательны первые четыре; для новой карточки клиента нужен телефон. Функция проверяет допустимость роли, уникальность логина и телефона, длину пароля и сразу создаёт строку в `user_security`, поэтому учётная запись готова к входу в приложение.

Проверка пароля по сохранённому хешу:

```sql
SELECT username, app_check_password('ClientPass123', password_hash) AS password_ok
FROM users WHERE username = 'ivanov';
```

Права на `create_account()` и `app_check_password()` есть только у `sto_admin`; остальным ролям PostgreSQL выполнение запрещено. Учитывайте, что открытый пароль при вызове кратковременно виден в `pg_stat_activity` и может сохраниться в истории `psql`.

## 8. Работа с JavaFX-интерфейсом

### 8.1. Вход в систему

1. Запустите приложение без параметров:

   ```powershell
   java -jar target\sto-db-module.jar
   ```

2. Дождитесь сообщения «Подключение к PostgreSQL» и появления формы входа.
3. Введите логин и пароль или нажмите на чип демонстрационной учётной записи (`admin`, `manager`, `master`, `client`) — логин и пароль подставятся автоматически.
4. Нажмите «Войти в систему».

Кнопка с изображением глаза переключает показ пароля. При пустых полях выводится сообщение «Введите логин и пароль», при неверных данных — «Неверный логин или пароль». В отличие от консольного режима, число попыток входа в JavaFX-интерфейсе не ограничено.

### 8.2. Оболочка и навигация

После входа открывается основное окно:

* **боковое меню** — только разделы, разрешённые роли: сотрудники видят «Обзор», «Заявки», «Клиенты», «Автомобили», «Услуги», «Мастера» и (кроме мастера) «Журнал статусов»; клиент — «Заявки» и «Услуги»;
* **верхняя панель** — название текущего раздела, строка поиска заявок и индикатор соединения с БД;
* **область контента** — карточки, таблицы и кнопки текущего раздела;
* **нижняя часть меню** — имя пользователя, его роль и кнопка выхода.

Поиск в верхней панели переносит в раздел «Заявки» и фильтрует список по введённому тексту. Кнопка выхода возвращает на экран входа и очищает данные пользователя; соединение с БД при этом сохраняется.

Ширина окна — от 1120 пикселей, высота — от 720. При изменении размера карточки и таблицы подстраиваются под доступное место.

### 8.3. Обзор

Раздел показывает сводку по сервису:

* карточки «Всего заявок», «В работе», «Завершено», «Выручка»;
* кольцевую диаграмму распределения заявок по статусам с легендой;
* таблицу активных заявок (новые и в работе) — двойной щелчок по строке открывает карточку заявки;
* блок «Последние события» с записями журнала статусов;
* блок «Справочники» с количеством клиентов, автомобилей, услуг и мастеров.

Кнопка «Обновить» повторно читает данные из PostgreSQL.

### 8.4. Заявки

Экран «Заявки» — основной рабочий инструмент:

* вкладки-фильтры «Все», «Новые», «В работе», «Завершённые», «Отменённые» с счётчиками;
* поиск по номеру, клиенту и автомобилю;
* таблица с колонками «Заявка», «Клиент», «Автомобиль», «Статус», «Стоимость» и кнопкой «Открыть»;
* кнопка «Новая заявка» — только у администратора и мастера-приёмщика.

Клиент видит в этом разделе только собственные заявки и не может создать новую, добавить услугу или закрыть заявку: соответствующие кнопки скрыты, а сервис дополнительно отклоняет такие вызовы. Попытка открыть чужую заявку по номеру завершается сообщением о недостатке прав.

**Создание заявки.** Доступно администратору и мастеру-приёмщику.

1. Нажмите «Новая заявка».
2. Выберите клиента — список автомобилей обновится автоматически.
3. Выберите автомобиль, мастера (необязательно) и введите описание неисправности.
4. Нажмите «Создать заявку».

Если клиентов в базе нет, приложение предложит сначала добавить клиента в разделе «Клиенты». Проверки: клиент и автомобиль должны существовать, автомобиль должен принадлежать выбранному клиенту, описание не должно быть пустым или длиннее 2000 символов, мастер должен быть активным.

**Карточка заявки.** Двойной щелчок по строке или кнопка «Открыть» показывает:

* статус и итоговую сумму;
* клиента с телефоном и e-mail;
* автомобиль, госномер и VIN;
* мастера, дату создания и дату закрытия;
* описание неисправности;
* таблицу услуг с количеством, зафиксированной ценой и суммой;
* журнал изменения статусов по этой заявке.

**Добавление услуги.** В карточке незавершённой заявки выберите услугу, укажите количество от 1 до 100 и нажмите «Добавить». Цена фиксируется в момент добавления (`order_services.price_at`), поэтому последующее изменение прайса не меняет стоимость уже оказанной услуги. После добавления карточка и список обновляются, появляется toast-уведомление.

**Закрытие заявки.** Кнопка «Завершить заявку» показывает подтверждение. После подтверждения:

* статус заявки становится «завершена»;
* триггер заполняет `closed_at`;
* в журнал `order_status_log` автоматически добавляется запись;
* список и карточка обновляются.

Добавлять услуги и закрывать можно только заявки в статусах «новая» и «в работе». Повторное закрытие отклоняется сообщением «Заявка уже завершена»; отменённую заявку завершить нельзя.

### 8.5. Клиенты

Раздел показывает таблицу клиентов: ФИО с инициалами, e-mail, телефон, количество автомобилей и дату добавления в базу.

* строка поиска фильтрует по ФИО, телефону и e-mail;
* кнопка «Добавить клиента» (только администратор и мастер-приёмщик) открывает форму с ФИО, телефоном и необязательным e-mail;
* кнопка «Открыть» или двойной щелчок по строке показывает карточку клиента.

В карточке клиента отображаются контакты, список автомобилей с госномерами и таблица заявок с автомобилем, статусом и стоимостью. Кнопка «Новая заявка» (у администратора и мастера-приёмщика) переходит в раздел «Заявки» и сразу подставляет выбранного клиента в форму создания.

### 8.6. Автомобили

Таблица содержит марку и модель, госномер, год выпуска, владельца и VIN. Поиск работает по марке, модели, номеру, VIN и имени владельца.

Кнопка «Добавить автомобиль» (доступна администратору и мастеру-приёмщику) открывает форму: владелец, марка, модель, год, госномер и VIN (необязательно). Год проверяется диапазоном 1950–2100, госномер должен быть уникальным.

### 8.7. Услуги

Прайс-лист представлен таблицей «Услуга», «Длительность», «Стоимость» и тремя карточками: количество услуг, средняя цена и средняя длительность. Поиск фильтрует список по названию.

Кнопка «Новая услуга» (только у администратора) создаёт позицию прайса: название, цена и необязательная длительность. Цена должна быть неотрицательной, длительность — положительной. Двойной щелчок по строке также открывает форму создания. Остальные роли видят прайс только для чтения.

### 8.8. Мастера

Раздел показывает карточки мастеров: инициалы, ФИО, специализацию, признак активности и текущую загрузку — количество активных заявок («новая» и «в работе») с индикатором выполнения. Сверху выводятся карточки «Всего мастеров», «Активных» и «В работе».

Мастера создаются вместе с учётной записью пользователя в БД, поэтому через интерфейс доступен только просмотр и обновление данных.

### 8.9. Журнал статусов

Журнал формируется триггером `trigger_log_status_change` при каждом изменении статуса заявки. В разделе доступны:

* фильтр по конкретной заявке или «Все заявки»;
* таблица с временем, номером заявки, прежним и новым статусом и автором изменения;
* счётчик показанных записей.

Журнал доступен только администратору и мастеру-приёмщику, открывается только для чтения и не редактируется из интерфейса. У автомобильного мастера и клиента раздел отсутствует в меню.

### 8.10. Уведомления и ошибки

Результат операций показывается toast-уведомлениями в правом нижнем углу: зелёные — успех, красные — ошибка, синие — информационные сообщения. Ошибки в формах выводятся под полями ввода.

Все запросы к PostgreSQL выполняются в фоновом пуле потоков, поэтому интерфейс не «зависает» во время загрузки. Результат возвращается в FX-поток через `Platform.runLater`.

## 9. Консольный режим

### 9.1. Вход в систему

Запустите приложение с параметром `--console`:

```powershell
java -jar target\sto-db-module.jar --console
```

Введите логин и пароль. При неверных данных выдаётся сообщение «Неверный логин или пароль» и предоставляется ещё одна попытка — всего их три. После третьей неудачной попытки приложение завершает работу.

Пароль не отображается при вводе, если запуск выполнен в терминале с поддержкой `System.console()`. В IDE и некоторых перенаправленных потоках пароль вводится обычной строкой.

### 9.2. Пункты меню

Состав меню зависит от роли и строится по тем же правам, что и JavaFX-интерфейс. Нумерация пунктов сквозная и может меняться, поэтому ориентируйтесь на названия:

| Пункт | Действие | Кому доступен | Что происходит в БД |
|---|---|---|---|
| Список заявок | чтение представления `v_order_total` | все роли | сотрудники видят все заявки, клиент — только свои |
| Список клиентов | чтение таблицы `clients` | admin, manager, master | — |
| Автомобили клиента | чтение `cars` по владельцу | admin, manager, master | — |
| Список услуг | чтение справочника `services` | все роли | — |
| Создать заявку | вызов функции `create_order` | admin, manager | создание заявки |
| Добавить услугу | вызов функции `add_service_to_order` | admin, manager, master | фиксация цены в `price_at` |
| Закрыть заявку | вызов функции `close_order` | admin, manager, master | статус «завершена», триггер пишет `closed_at` |
| Рассчитать стоимость | вызов функции `calculate_order_total` | все роли | — |
| Заявки клиента | вызов функции `get_client_orders` | все роли | клиенту подставляется его `client_id` автоматически |
| Журнал статусов | чтение `order_status_log` | admin, manager | — |
| Проверить соединение | `SELECT version()` через пул | все роли | — |
| Выход | закрытие пула и завершение приложения | все роли | — |

Для клиента ввод `ID клиента` не запрашивается: идентификатор берётся из учётной записи, поэтому чужие заявки недоступны.

### 9.3. Просмотр заявок

Выберите пункт «Список заявок». Приложение выведет таблицу:

```
ID   Клиент                           Авто          Статус           Стоимость
4    Иванов Иван Иванович             Е321ОР64      в работе           6200.00
3    Сидоров Алексей Петрович         С789МН64      завершена          5500.00
2    Петрова Мария Сергеевна          В456ЕК64      в работе           2800.00
1    Иванов Иван Иванович             А123ВС64      новая                    0
```

Стоимость рассчитывается представлением `v_order_total` на основании услуг, добавленных в заявку, с учётом зафиксированной цены `price_at`.

### 9.4. Создание заявки

1. Выберите пункт «Создать заявку».
2. Приложение покажет список клиентов. Введите `ID клиента`.
3. Выберите автомобиль из списка автомобилей этого клиента.
4. Выберите мастера или введите `0`, чтобы создать заявку без мастера.
5. Введите описание неисправности (обязательное поле, до 2000 символов).

После успешного создания выводится номер заявки, например «Создана заявка №14».

Проверки, которые выполняет приложение:

* клиент и автомобиль должны существовать;
* автомобиль должен принадлежать выбранному клиенту;
* описание не должно быть пустым или длиннее 2000 символов;
* выбранный мастер должен существовать и быть активным.

### 9.5. Добавление услуги в заявку

1. Выберите пункт «Добавить услугу».
2. Приложение покажет справочник услуг с ценами.
3. Введите `ID заявки`, `ID услуги` и количество от 1 до 100.

Цена услуги фиксируется в момент добавления (`order_services.price_at`), поэтому последующее изменение прайса не меняет стоимость уже оказанной услуги.

Запрещено добавлять услуги в заявку со статусом «завершена» или «отменена». Ограничение действует и в приложении, и в триггере БД.

### 9.6. Закрытие заявки

1. Выберите пункт «Закрыть заявку».
2. Введите `ID заявки`.

После закрытия:

* статус заявки становится «завершена»;
* триггер заполняет `closed_at`;
* в журнал `order_status_log` автоматически добавляется запись;
* приложение выводит итоговую стоимость.

Повторное закрытие завершённой заявки отклоняется сообщением «Заявка уже завершена». Отменённую заявку завершить нельзя.

### 9.7. Расчёт стоимости и заявки клиента

* Пункт «Рассчитать стоимость» запрашивает `ID заявки` и выводит сумму через `calculate_order_total`.
* Пункт «Заявки клиента» для сотрудника запрашивает `ID клиента`, а для клиента использует `client_id` из учётной записи и выводит заявки: номер, автомобиль, статус, стоимость и дату создания.

Сумма из пункта «Рассчитать стоимость» должна совпадать со стоимостью в списке заявок для той же заявки — это проверяется автоматическим тестом `viewTotalEqualsStoredFunctionResult`.

### 9.8. Журнал статусов

Пункт «Журнал статусов» доступен администратору и мастеру-приёмщику. Можно ввести `ID заявки`, чтобы увидеть историю только по ней, или нажать `Enter`, чтобы вывести весь журнал.

```
ID   Заявка Было     Стало    Когда                Кто
--------------------------------------------------------------------------------
1    3      1        4        2026-11-10 12:34:56  sto_admin
```

Журнал ведётся триггером `trigger_log_order_status` и не редактируется из приложения.

## 10. Типичные ошибки и способы устранения

| Сообщение / симптом | Причина | Что делать |
|---|---|---|
| «Нет подключения к базе данных» на экране JavaFX | контейнер не запущен, неверный порт или пароль | выполнить `docker compose ps`, проверить `db.url`, `db.username`, `db.password`, нажать «Повторить подключение» |
| `Не удалось подключиться к БД за 4 попыт(ки)...` | PostgreSQL недоступен | запустить `docker compose up -d`, проверить порт `5434` |
| `Connection refused` / `08001` | PostgreSQL недоступен | запустить контейнер и повторить подключение |
| `28P01` / таймаут при неверном пароле | неверные учётные данные роли БД | исправить `db.password` или `STO_DB_PASSWORD` |
| «Неверный логин или пароль» | неверные данные пользователя приложения | использовать учётную запись из раздела 7 |
| «Превышено количество попыток входа» | три неудачных входа в консольном режиме | перезапустить приложение и проверить раскладку клавиатуры |
| «Ошибка: Клиент с id=... не найден» | введён несуществующий ID (консоль) | посмотреть список клиентов в пункте `2` |
| «Ошибка: Автомобиль ... принадлежит другому клиенту» | несоответствие пары клиент—автомобиль | выбрать автомобиль из списка, предложенного приложением |
| «Ошибка: Количество должно быть от 1 до 100» | введено 0, отрицательное число или больше 100 | ввести корректное количество |
| «Ошибка: Нельзя добавить услугу в заявку со статусом «завершена»» | заявка уже закрыта | создать новую заявку |
| «Ошибка: Заявка уже завершена» | повторное закрытие | выбрать другую заявку |
| «Ошибка: Описание неисправности обязательно» | пустое описание | ввести текст неисправности |
| `Ошибка БД: ... SQLState: 23505` | дубликат уникального значения | изменить телефон, номер или VIN |
| `Ошибка БД: ... SQLState: 23503` | нарушена ссылочная целостность | проверить, что клиент, автомобиль и услуга существуют |
| `Ошибка БД: ... SQLState: 57014` | превышено время выполнения запроса | повторить операцию или обратиться к администратору |
| `Unsupported JavaFX configuration: classes were loaded from 'unnamed module'` | предупреждение при запуске JavaFX из shaded jar | сообщение безобидно, работа продолжается штатно |
| `JavaFX runtime components are missing` | попытка запустить JavaFX не через точку входа `StoApplication` или без зависимостей | использовать `java -jar target\sto-db-module.jar` или `.\mvnw.cmd javafx:run` |
| Кириллица отображается некорректно в консоли | кодировка терминала | использовать Windows Terminal или выполнить `chcp 65001` |

Полный перечень ожидаемых ошибок приведён в [expected-errors.md](expected-errors.md).

## 11. Остановка и повторный запуск

Закройте окно JavaFX или нажмите `Ctrl+C` в терминале, где запущено приложение. В консольном режиме используйте пункт `0`.

Остановить БД без потери данных:

```powershell
docker compose stop
```

Запустить снова:

```powershell
docker compose start
```

Полностью удалить данные и пересоздать стенд:

```powershell
docker compose down -v
docker compose up -d
```

> Команда `down -v` **удаляет все данные**: заявки, клиентов, автомобили и журнал. Используйте её только для возврата к исходному демонстрационному состоянию.

## 12. Резервное копирование и восстановление

Создать дамп базы:

```powershell
docker exec sto-postgres pg_dump -U postgres -d sto -F c -f /tmp/sto.dump
docker cp sto-postgres:/tmp/sto.dump .\sto.dump
```

Восстановить из дампа:

```powershell
docker cp .\sto.dump sto-postgres:/tmp/sto.dump
docker exec sto-postgres pg_restore -U postgres -d sto --clean --if-exists /tmp/sto.dump
```

Для учебного стенда резервное копирование не является обязательным, но позволяет сохранить результаты демонстрации.

## 13. Ограничения учебной версии

* разграничение доступа работает по роли пользователя, но приложение подключается к БД под ролью `sto_admin` с широкими правами (риск SEC-02);
* роль `client` изолирована на уровне приложения (`users.client_id`, фильтрация в `OrderService`) и представления `v_my_orders`; при подключении под `sto_client` базовые таблицы недоступны;
* роли `manager` и `master` могут менять только `status_id`; прямое изменение `closed_at` запрещено (SEC-03 устранён);
* пароли демонстрационных пользователей и роли БД находятся в репозитории (риск SEC-04);
* соединение с PostgreSQL не защищено TLS (риск SEC-05);
* порт `5434` опубликован на все интерфейсы хоста (риск SEC-08);
* таблицы `user_security` и `login_attempts` созданы, но автоматическая блокировка после неудачных входов пока не включена (SEC-06);
* отсутствует журналирование действий пользователя на уровне приложения (SEC-07).

Меры по устранению рисков и приоритеты приведены в [05_Безопасность.md](05_Безопасность.md).

## 14. Часто задаваемые вопросы

**Нужно ли устанавливать PostgreSQL отдельно?**  
Нет. PostgreSQL поставляется в Docker-образе и запускается через `docker compose`.

**Нужно ли устанавливать JavaFX SDK?**  
Нет. JavaFX 23.0.1 подключается через Maven и входит в `target/sto-db-module.jar`. Отдельные библиотеки и сборщики фронтенда проекту не нужны.

**Можно ли использовать другой порт?**  
Да. Измените проброс порта в `docker-compose.yml` и значение `db.url` в `application.properties` или переменной `STO_DB_URL`.

**Почему `--demo` каждый раз создаёт новую заявку?**  
Сценарий специально выполняет полный цикл записи, чтобы продемонстрировать работу функций и триггеров. Для сброса данных используйте `docker compose down -v`.

**Почему интеграционные тесты пропускаются?**  
Если контейнер PostgreSQL не запущен, интеграционные тесты помечаются как skipped. Запустите `docker compose up -d` и повторите `.\mvnw.cmd test`.

**Где посмотреть результаты тестирования?**  
В [04_Результаты_тестирования.md](04_Результаты_тестирования.md) и каталоге `docs/evidence/`.

**Что делать при ошибке `function create_order(...) does not exist` при старте контейнера?**  
Убедиться, что используется исправленная версия `sto.sql`, в которой блок `GRANT EXECUTE` расположен после создания функций. Затем пересоздать том: `docker compose down -v` и `docker compose up -d`.

## 15. Контрольный чек-лист пользователя

- [ ] Docker запущен, контейнер `sto-postgres` в состоянии `healthy`.
- [ ] `java -jar target\sto-db-module.jar --check` завершается успешно.
- [ ] `java -jar target\sto-db-module.jar` открывает окно JavaFX и экран входа.
- [ ] Вход под нужной ролью выполнен, в боковом меню отображаются имя, роль и только доступные разделы.
- [ ] Для `admin` доступны все семь разделов и кнопки создания; для `master` скрыт «Журнал статусов» и создание заявок; для `client` видны только «Заявки» (свои) и «Услуги».
- [ ] Обзор, «Заявки», «Клиенты», «Автомобили», «Услуги», «Мастера» и «Журнал статусов» показывают данные из БД в соответствии с правами роли.
- [ ] Создание, добавление услуги и закрытие заявки выполняются без ошибок у ролей, которым эти действия разрешены.
- [ ] Клиент не видит заявки других клиентов и не может открыть их по номеру.
- [ ] Журнал статусов содержит запись о закрытии.
- [ ] Данные после перезапуска приложения сохраняются.
- [ ] Консольные режимы `--check`, `--console` и `--demo` по-прежнему работают.
