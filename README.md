# Модуль доступа к базе данных СТО

Учебный проект по профессиональному модулю **ПМ.01 «Разработка модулей программного обеспечения для компьютерных систем»** (УП.01.02, специальность 09.02.07).

Приложение на Java реализует модуль доступа к БД станции технического обслуживания (СТО) автомобилей. PostgreSQL развёртывается в Docker, схема и бизнес-правила взяты из файла [`sto.sql`](sto.sql), параметры подключения вынесены в `application.properties`.

Модуль работает в двух режимах: консольном (интерактивное меню и demo-сценарий) и веб-режиме `--web` — встроенный REST API на JDK `HttpServer` плюс одностраничный интерфейс на Angular, который читает и изменяет реальные данные PostgreSQL.

## Быстрый старт

### 1. Запуск PostgreSQL в Docker

```powershell
docker compose up -d
docker compose ps
```

При первом запуске автоматически выполняются:

* [`sto.sql`](sto.sql) — таблицы, индексы, представление, роли, права, функции и триггеры;
* [`docker/init/02_seed.sql`](docker/init/02_seed.sql) — демонстрационные пользователи, клиенты, автомобили, услуги и заявки.

Проверить готовность:

```powershell
docker exec sto-postgres pg_isready -U postgres -d sto
```

Параметры стенда по умолчанию: `localhost:5434`, БД `sto`, суперпользователь `postgres/postgres`.
Порт и пароль можно изменить через переменные окружения (см. `.env.example`).

Полный сброс БД (удаляет том с данными и выполняет init-скрипты заново):

```powershell
docker compose down -v
docker compose up -d
```

### 2. Сборка и запуск приложения

```powershell
.\mvnw.cmd clean package
java -jar target\sto-db-module.jar
```

Linux/macOS:

```bash
./mvnw clean package
java -jar target/sto-db-module.jar
```

Режимы запуска:

```powershell
java -jar target\sto-db-module.jar              # интерактивное меню
java -jar target\sto-db-module.jar --demo       # сквозной демонстрационный сценарий
java -jar target\sto-db-module.jar --check      # проверка соединения и версии PostgreSQL
java -jar target\sto-db-module.jar --list-orders
java -jar target\sto-db-module.jar --web        # REST API + веб-интерфейс на http://localhost:8080
java -jar target\sto-db-module.jar --help
```

Веб-режим раздаёт REST API по адресу `http://localhost:8080/api` и собранный Angular-интерфейс по адресу `http://localhost:8080/`. Порт API задаётся переменной `STO_WEB_PORT` (по умолчанию `8080`).

### 3. Сборка и запуск фронтенда

```powershell
cd frontend
npm ci
npm run build          # сборка в frontend\dist\sto-frontend\browser
cd ..
java -jar target\sto-db-module.jar --web
```

Для разработки с горячей перезагрузкой:

```powershell
cd frontend
npm start              # http://localhost:4200
```

Angular-приложение обращается к API по абсолютному адресу `http://localhost:8080/api`, поэтому при `npm start` Java-сервер `--web` должен быть запущен параллельно. Если интерфейс ещё не собран, `--web` отвечает на `/` подсказкой выполнить `npm run build` в каталоге `frontend`.

### 4. Тестовые учётные записи

| Логин | Пароль | Роль |
|---|---|---|
| `admin` | `admin123` | администратор |
| `manager` | `manager123` | мастер-приёмщик |
| `master` | `master123` | автомобильный мастер |
| `client` | `client123` | клиент СТО |

Пароли хранятся в БД в виде bcrypt-хешей (`pgcrypto`, `crypt()`); в коде и в логах пароли не сохраняются.

## Настройка подключения

Файл [`src/main/resources/application.properties`](src/main/resources/application.properties):

```properties
db.url=jdbc:postgresql://localhost:5434/sto
db.username=sto_admin
db.password=admin_pass
db.pool.maximumPoolSize=5
db.retry.maxAttempts=4
```

Приоритет источников:

1. переменные окружения `STO_DB_URL`, `STO_DB_USERNAME`, `STO_DB_PASSWORD`, `STO_DB_MAX_POOL_SIZE`, `STO_DB_RETRY_MAX_ATTEMPTS`;
2. файл, указанный через `-Dconfig.file=D:\path\application.properties`;
3. `application.properties` в classpath.

Пароль в репозитории приведён только для локального учебного стенда. Для реального запуска используйте переменную `STO_DB_PASSWORD` или хранилище секретов.

## Возможности приложения

### Консольный режим

* аутентификация пользователя по логину/паролю (проверка bcrypt-хеша средствами PostgreSQL);
* просмотр заявок через представление `v_order_total` с расчётом стоимости;
* создание заявки, добавление услуг, закрытие заявки через хранимые функции `create_order`, `add_service_to_order`, `close_order`;
* расчёт стоимости через `calculate_order_total`;
* список заявок клиента через `get_client_orders`;
* работа со справочниками клиентов, автомобилей, услуг и мастеров;
* просмотр журнала изменений статусов `order_status_log`;
* ролевое меню (администратор, менеджер, мастер, клиент);
* повторные попытки подключения при временной недоступности БД;
* трансляция `SQLException` в предметные исключения (дубликат, FK, NOT NULL, разрыв связи, синтаксис SQL).

### Веб-интерфейс (`--web`)

* страница входа с демонстрационными учётными записями и регистронезависимым логином;
* дашборд: счётчики заявок, распределение статусов, активные заявки, выручка, последние события журнала;
* заявки: фильтры по статусу, поиск, создание, карточка заявки, добавление услуг, закрытие с записью в журнал;
* клиенты: карточки, создание, карточка клиента с автомобилями и историей заявок;
* автомобили, услуги и мастера: справочники, поиск, сортировка, создание записей;
* журнал статусов с фильтром по заявке и группировкой по дням;
* адаптивная вёрстка, тёмный sidebar, модальные окна и toast-уведомления;
* все данные читаются и записываются в PostgreSQL через REST API модуля, моки не используются.

### REST API

| Метод и путь | Назначение |
|---|---|
| `GET /api/health` | состояние сервера и подключения к БД |
| `POST /api/login` | вход по логину и паролю |
| `GET /api/orders` | список заявок с итоговой стоимостью |
| `POST /api/orders` | создание заявки |
| `GET /api/orders/{id}` | карточка заявки: клиент, авто, услуги, сумма |
| `GET /api/orders/{id}/log` | история статусов конкретной заявки |
| `POST /api/orders/{id}/services` | добавление услуги в заявку |
| `POST /api/orders/{id}/close` | закрытие заявки |
| `GET /api/clients`, `POST /api/clients` | список и создание клиентов |
| `GET /api/clients/{id}` | клиент с автомобилями и историей заявок |
| `GET /api/cars`, `POST /api/cars` | список и создание автомобилей |
| `GET /api/services`, `POST /api/services` | прайс-лист и создание услуги |
| `GET /api/masters` | список мастеров |
| `GET /api/masters/workload` | загрузка мастеров активными заявками |
| `GET /api/statuses` | справочник статусов заявок |
| `GET /api/log` | журнал изменений статусов |

CORS открыт для локальной разработки. API не выдаёт токенов: браузер хранит сведения о пользователе в `localStorage` и передаёт имя автора в запросах. Это осознанное упрощение учебного стенда, а не промышленная схема аутентификации.

## Примечание к `sto.sql`

При подготовке стенда в исходном скрипте исправлен порядок выполнения: блок `GRANT EXECUTE ON FUNCTION ...` перенесён после создания функций. Без этого `docker-entrypoint-initdb.d` останавливал инициализацию с ошибкой `function ... does not exist` (PostgreSQL выполняет init-скрипты с `ON_ERROR_STOP=1`). Содержимое схемы, прав и бизнес-правил не изменялось.

## Ограничения учебного стенда

* пароли ролей БД и демонстрационных пользователей заданы в SQL-скрипте и предназначены только для локального запуска;
* приложение подключается к БД под ролью `sto_admin`; для промышленной эксплуатации следует создать отдельную роль с минимально необходимыми правами;
* веб-интерфейс — учебный: нет токенов и разграничения доступа на уровне API, сведения о пользователе хранятся в `localStorage`; проверка ролей ограничена клиентской навигацией;
* консольный режим оставлен для демонстрации модуля доступа к данным, а веб-режим — для наглядной работы с той же базой;
* автотесты покрывают Java-модуль; для Angular-приложения отдельные unit- и e2e-тесты не предусмотрены, проверка выполнялась вручную в браузере.
